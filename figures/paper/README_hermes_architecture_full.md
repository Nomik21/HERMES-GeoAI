# HERMES full architecture figure — v3 (font fix + precision pass)

## What changed in v3
Polishing pass on top of the v2 compact redesign:
- **Font switched from "Helvetica" to "Arial"** for the graph, all nodes, all cluster labels, and all edges. "Helvetica" is not an installed Windows font name, so the WASM Graphviz/resvg toolchain was silently substituting a narrow fallback font (the cause of the "narrow/decorative" look and the I/l ambiguity in agent names). Arial is confirmed installed (`Get-ChildItem`-verified) and renders cleanly.
- **Persisted output paths made precise**, matching `pipeline_state.py` exactly: agent boxes now show `outputs/intermediate/<case_id>_{gpa,gira,gdaa}.json`; the artefact-row icons show the shorter `<case_id>_gpa.json` form (full path already stated once, above, in the agent box — kept short here to stay compact). GRA's box shows `outputs/<case_id>.json/.md/.html` per the requested simplified form — see the caption file's supplementary note for the caveat that the real save path nests under a scenario subfolder.
- **GDAA wording corrected**: "object-indicator estimation" → "object-indicator detection" (matches the actual `detect_damage_objects_zero_shot` scenario).
- **GRA wording updated** to name the locked evidence-set step explicitly: "Role: locked evidence-set synthesis + reporting".
- **Eval 5 and Eval 6 inputs made explicit** via edge labels: Eval 5 ← "report + evidence set", Eval 6 ← "final report" (both still sourced from the one GRA report artefact, since the evidence chain is a field inside that report, not a separate file).
- **Capitalization normalized**: "OpenAI GPT-4.1-mini", "Gemini 2.5 Flash", "GeoImageRestoration Agent", "GeoDamageAnalysis Agent", "GeoReasoning Agent".
- Layout otherwise unchanged from v2: aspect ratio is now **≈1182×634 (≈1.86:1)**, still a compact landscape banner close to 16:9, not panoramic.

## Rendering toolchain used
No system Graphviz (`dot`) binary was available in this environment. Rendering was done with two on-demand npm packages (no permanent install; `npx -y` fetches them into the npm cache):
```
npx -y @hpcc-js/wasm-graphviz-cli -T svg hermes_architecture_full.dot > hermes_architecture_full.svg
npx -y resvg-cli --fit-width 3600 --background white hermes_architecture_full.svg hermes_architecture_full.png
```
`@hpcc-js/wasm-graphviz-cli` is a WebAssembly build of the real Graphviz `dot` engine (confirmed via its SVG output header: "Generated by graphviz version 16.1.0"), so the layout is authentic Graphviz `dot`, not an approximation.

As the filename and caption indicate, this is intended as **Figure 4.1** in Chapter 4 (System Architecture) — i.e., it now *replaces* the earlier, simpler Figure 4.1 sketch rather than sitting alongside it, since it covers the same architectural ground (four agents, orchestration, GIRA's optional/guarded status) at a level of implementation detail suitable to stand as the thesis's primary architecture figure. If the thesis still needs an even simpler *conceptual-only* diagram earlier in Chapter 3 or 4 for a first-pass reader, keep that as a separate, unlabelled sketch — but this file is the one to cite as "Figure 4.1" going forward.

## Print/insert guidance
- **Word thesis:** insert the SVG (Word 2016+ supports native SVG insertion) at roughly half a page width to two-thirds of a page width; at ≈1.86:1 it fits comfortably in a portrait page without rotation, unlike the v1 banner.
- **Two-column paper:** fits as a single-column figure at full column width, or a bit larger spanning both columns if finer text legibility is wanted.
- If you edit the `.dot` file and the layout changes significantly, re-check the aspect ratio (`grep -o 'viewBox="[^"]*"' hermes_architecture_full.svg`) before re-exporting the PNG.
